# h-medi 데이터 증류 (data distillation)

[English](README.md) · **한국어**

원시 **h-medi** IMU 장비 로그를, 행(row)마다 서 있음/걷기 판정과 그 신뢰도로 증류해 내는
단계형 파이프라인. 확신이 서지 않는 행에는 **그 이유를 명시한 채로 판정을 보류**한다.
**연산은 결정론적 코드가 하고, 판단만 정해진 지점에서 Claude 에이전트가 한다** — 모든
결정은 기록되며 재현 가능하다.

[Claude Agent SDK](https://docs.claude.com/en/docs/agent-sdk/overview) (Python) 기반.

> **이름에 대하여.** 이 저장소의 모든 측정 대상 — 코퍼스, 장비, 데이터 — 은 **h-medi**다.
> 작업 디렉터리와 git 리모트는 둘 다 `hurotics-autolabel`이다. 파이프라인보다 먼저 붙은
> 이름이고, 데이터가 아니라 벤더를 가리킨다. HUROTICS는
> 벤더 이름이다. `archive/`나 `runs/keep/agent_runs/*/system_prompt.txt` 안에 남아 있는
> *H-CARE*는 당시 기록을 그대로 얼려 둔 것이며 의도적으로 고치지 않았다 —
> [여기 남아 있는 "h-care"의 의미](#여기-남아-있는-h-care의-의미) 참고.

> **이 문서는 [`README.md`](README.md)의 한국어 쌍둥이다.** 두 문서가 다르면 원본이 맞다.
> 아래 헤드라인 수치는 `stages/breakdown.py`가 이 파일에 대해서도 기계적으로 검사한다.

## 여기서 "증류"란 구체적으로 무엇인가

각 단계는 남기는 것보다 버리는 것이 많고, **버리는 것 자체가 목적**이다. 살아남은 컬럼은
전부 하류의 어떤 수치가 거슬러 올라갈 수 있는 컬럼이다.

| 무엇에서 | 무엇으로 | 무엇을, 왜 버리는가 |
|---|---|---|
| 원시 장비 로그 | **45컬럼 계약**, `Time` … `Total Gait Length` | 인덱스 44 이후의 variant별 꼬리. 그건 측정값이 아니라 펌웨어 세대다 |
| 45컬럼 | **측정된** 채널만, 표준 **100 Hz** 격자 위로 | 펌웨어가 *계산한* 모든 것 — Cadence, Stride Length, GCP, 어드미턴스, PID 상태 |
| 정제된 프레임 | 파일당 **`channel_trust.json`** 하나 | 프레임 자체. S1은 프레임을 재고 나서 버린다 ([데이터 배치](#데이터-배치) 참고) |
| 측정 채널 전체 | **회전 채널 4개** — `L/R_ang_LPF`, `L/R_angvel_LPF` | 선형 이동을 담는 모든 채널. 트레드밀 위에서는 분명히 걷고 있는데도 ~0을 가리켜 분류기를 적극적으로 오도한다 (`DOMAIN_NOTES` §5.7) |
| 채널 4개 × 2초 윈도우 | **윈도우 특징 38개** (`extratrees400_drop_moments38`) | 어블레이션 대장이 정당화하지 못한 모멘트 특징 4개 |
| 윈도우당 38개 특징 | 행마다 **확정 판정 1개**, 또는 이유가 붙은 보류 | 앙상블이 충분히 확신하지 못한 행 — 출하 임계값에서 전체의 15.3% |

마지막 줄이 이것을 단순한 분류기가 아니라 증류로 만든다. **커버리지 손실은 의도된
것**이고 그 근거는 `OPERATING_POINTS.md`에 있으며, 버려지는 행은 조용히 사라지지 않고
이유를 달고 나간다.

## 이 저장소의 모든 명령

나머지는 전부 러너가 호출하는 모듈이다 — `python run_pipeline.py --keys`가 그 목록을 한 줄씩
보여 주고, 한 단계씩 손으로 돌릴 때를 위해 [실행하기](#실행하기)에 정리해 두었다.

| 명령 | 무엇을 위한 것인가 | 언제 |
|---|---|---|
| `python run_pipeline.py` | **파이프라인 전체.** `data/raw` → `runs/breakdown.md`, 모든 단계가 자기 산출물로 게이트된다. `--with-agents`는 유료 리뷰를 추가하고, `--from KEY`는 재개한다 | 새 데이터가 들어왔을 때, 또는 어떤 단계든 바뀌었을 때 |
| `python -m stages.s2_ml.label FILE` | **산출물 그 자체.** 녹화 하나를 넣으면 입력 행 수만큼 행이 나오고, 각 행은 `Label` / `guess` / `confidence` / `ambiguous` / `reason`을 달고 있다. 원시 장비 로그와 `lpf_view` 파일 둘 다 받는다 | 녹화 하나에 라벨을 붙일 때 |
| `python -m stages.s2_ml.label_all` | 같은 산출물을 `data/raw` 전체에 한 번에. 파일당 코드 경로는 동일하다. 파이프라인 16단계이기도 해서 전체 실행이면 자동으로 만들어진다 | 방금 학습시키지 않은 챔피언으로 코퍼스 전체에 라벨을 붙일 때 |
| `python -m stages.s1_clean.validate FILE` | **이 녹화를 애초에 쓸 수 있나?** 라벨 없이, 모델 없이 하는 사전 점검: 샘플링 레이트, 결측 구간, 세그먼트 길이, 채널 존재 여부. 돈을 쓰기 전에 답한다 | 새 녹화가 도착했고 점수를 매길 수 있는지 알고 싶을 때 |
| `python -m stages.s3_physics.inspect_window REV TRIAL --t SECONDS` | **의심 윈도우 하나를 눈으로 판정한다.** 한 시각 주변의 원시 양다리 각도차 궤적과, 스왑 규칙이 센 ±1° 교차를 출력한다 | 리뷰가 어떤 윈도우를 오라벨 의심으로 표시했고 사람이 결론을 내야 할 때 |

제목에 개수를 쓰지 않은 것은 의도적이다. 한때 "다섯 개."라고 적혀 있었고, 어긋났고,
그 어긋남은 `archive/needtowrite.md` §4에 반복하지 말아야 할 결함으로 기록돼 있다.

## 이 순서로 먼저 읽을 것

| 파일 | 무엇인가 |
|---|---|
| **`DOMAIN_NOTES.md`** | h-medi 코퍼스가 우리에게 어렵게 가르쳐 준 모든 것. 모든 에이전트 프롬프트에 주입된다. **데이터를 건드리기 전에 읽을 것.** |
| **`caveats.md`** | 이 파이프라인이 취약한 지점: 근거가 얇은 상수, 인정하고 넘어간 불완전함, 검증되지 않은 경로, 의도적 누락. 숫자를 믿기 전에 읽을 것. |
| **`OPERATING_POINTS.md`** | 보류 임계값: 각 프리셋이 무엇을 치르고 무엇을 사는지, 기본값이 왜 0.85인지. |
| **[`README.md`](README.md)** | 이 문서의 원본 (English). 둘이 다르면 원본이 맞다. |
| 이 문서 | 실행 방법 (한국어). |
| **`RUNBOOK.md`** | 각 명령이 실제로 *건드리는 것*: 모든 입력 경로, 모든 단계의 게이트, 쓰는 파일 전부. 다른 문서가 아니라 코드를 읽어서 유도했다. 이 문서가 "무엇을 실행하라"고 했고 "그래서 어디에 뭐가 떨어졌는지" 알아야 할 때 읽는다. |
| **`runs/README.md`** | `runs/` 트리 자체 — 지워도 되는 것, 절대 복구 불가능한 것, 그리고 그 이유. |

`DOMAIN_NOTES.md`는 배경 지식이 아니라 **이 파이프라인이 이런 모양인 이유**다. 모든 항목에
출처 태그가 붙는다: **[measured]** (해당 단계를 다시 돌리면 재현됨), **[reported]** (사람이
그렇게 말했고, 독립 검증은 안 됨), **[decided]** (설계 선택), **[open]** (알려진 미지).
하나만 읽어야 한다면 §1.3 — 컬럼 앞의 숫자 접두사는 거짓말이고, 위치 기반 인덱싱은 코퍼스
일부에서 펌웨어 걸음 수 카운터를 이동 상태로 조용히 바꿔치기하면서 **에러 한 번 내지 않는다**.

## 설치

**Python 3.10+** 필요.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1      # 막히면: Set-ExecutionPolicy -Scope Process RemoteSigned
pip install -r requirements.txt
Copy-Item .env.example .env
```

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

API 키는 [Console](https://platform.claude.com)에서 발급한다. SDK가 프로세스 환경변수에서
읽고 `run_pipeline.py`가 `load_dotenv()`를 호출하므로 `.env`만 있으면 된다.

> **Console에서 월 지출 상한을 걸어 둘 것.** 이 안전장치는 저장소 안에서 강제할 수 없다 —
> 에이전트 단계가 드는 만큼 쓰는 것을 여기 있는 무엇도 막지 못한다.

**새 터미널을 열 때마다 venv를 활성화해야 한다.** 이걸 잊는 것이 여기서 `ModuleNotFoundError`가
나는 가장 흔한 원인이다.

## 데이터 배치

```
data/raw/<YYYYMMDD[_n]>/*.csv       라벨 없는 h-medi 장비 로그. 장비가 쓴 그대로
data/labeled/rev*/csv/*.csv         정답 주석 코퍼스. 절대 raw에 섞지 않는다
data/clean/<session>/
    <stem>.channel_trust.json       S1의 출력이자, 파일당 유일하게 남기는 것: 그 녹화에서
                                    실측한 자이로 단위와 Deg->Gyro 치환, 그리고 어느 축이
                                    판정을 보류했는지
```

**S1의 산출물은 코퍼스의 사본이 아니라 판정이다.** clean은 각 파일을 표준 100 Hz 격자로
리샘플하고, 측정 채널만 남기고, 자이로를 deg/s로 정규화한 다음 — *프레임을 재고 나서
버린다*. 하류의 무엇도 정제된 프레임을 읽지 않는다. `label.py`는 라벨링 시점에 원시 로그에서
특징을 다시 만들고, 어떤 축을 읽어도 되는지는 그 파일의 `channel_trust.json`에 묻는다.
S2는 `data/labeled`에서 학습한다. 신호의 사본을 하나 더 저장해 두면, raw와 계속 맞춰 줘야 할
대상이 하나 더 생길 뿐이다.

**세션 날짜는 파일명이나 컬럼이 아니라 폴더에서 온다** (§manifest). 파일명에 든 날짜는
어떤 때는 내보내기 날짜고 어떤 때는 그냥 틀렸다. 이 코퍼스가 신뢰하는 유일한 메타데이터는
디렉터리다.

**`data/raw/` 밑에 `Label` 컬럼이 나타나면 그건 스키마 변종이 아니라 오염 사고다.** raw는
정의상 라벨이 없다 — 거기 `Label`이 있다는 건 주석 데이터가 입력 트리에 복사됐다는 뜻이고,
그 이후에 계산된 모든 정확도 수치는 무가치하다.

**격리(quarantine)는 삭제가 아니라 장부다.** S1이 정제하지 못한 파일은 이유와 함께
`runs/regen/s1_clean/quarantine.jsonl`에 기록되고 디스크에는 그대로 남는다. 이 파이프라인의
무엇도 원시 데이터를 지우지 않는다.

### git에 들어가는 것과 안 들어가는 것

`data/` 전체, `.env`, `tracker/`, 그리고 `archive/` 밑에 새로 생기는 것은 gitignore된다.
**h-medi 녹화는 git을 통해 이 기계를 떠나지 않는다.**

`runs/`와 `labeled_raw/`는 **가치가 아니라 크기**로 걸러진다. 빠지는 것은 무거운 바이너리 —
학습된 모델, 행 단위 점수, 세션당 수 GB짜리 라벨링 CSV — 이고 전부 `train.py`와
`label_all.py`가 필요할 때 다시 만든다. 그 외의 것은 작고, 코드나
`OPERATING_POINTS.md`에서 하는 주장의 증거이므로 그 주장과 함께 다닌다. 스스로를 설명하는
`.gitignore`를 볼 것.

**이건 `runs/regen` 대 `runs/keep`과는 다른 질문이다.** 후자는 전체 실행으로 그 파일을 다시
만들 수 있느냐로 나뉜다 — `rm -rf runs/regen`은 안전하고 때로는 옳은 선택이지만,
`runs/keep` 밑의 것은 어떤 대가로도 복구되지 않는다.
`runs/keep/s2_ml/roweval_lockbox.json`은 rev8 판독이고 — 대체된 2026-08-03 판독은
`roweval_lockbox.2026-08-03.json`으로 그 옆에 남는다. 재판독은 산출물을 갈아치우지만
기록을 갈아치우지는 않는다 —
`runs/keep/s2_ml/experiments.jsonl`은 특징 집합이 지금에 이른 경위의 유일한 기록이며,
`runs/keep/ablations/`에는 `champion_spec.json`이 기각한 항목들의 근거인 LOCO 평가가 들어
있다. 색인은 `runs/README.md`고, `runs/` 밑 모든 경로의 유일한 정의는 `runslayout.py`다 —
각 단계가 다시 적는 대신 import한다.

## 실행하기

### 전체

```powershell
python run_pipeline.py                  # 결정론적 본체 + 검증 단계
python run_pipeline.py --with-agents    # + 유료 에이전트 리뷰 (API 크레딧 소모)
python run_pipeline.py --keys           # 모든 단계 키와, 그 단계가 답하는 질문 한 줄
python run_pipeline.py --dry-run        # 무엇이 어떤 순서로 돌지만, 돌리지 않고
```

각 단계는 독립 서브프로세스이고, 다음 단계가 시작되기 전에 자기 **게이트 산출물**을 반드시
만들어야 한다 — 아무것도 쓰지 않고 0으로 종료한 단계는 실행을 멈춘다. 그러지 않으면 다음
단계가 이전 실행의 파일을 읽고 지난주 숫자를 조용히 보고하게 된다. 실패하면 그 단계에서
재개할 `--from <key>`를 출력한다.

`--dry-run`은 아무것도 읽지 않고 아무것도 쓰지 않으므로, 데이터가 하나도 없는 체크아웃에서도
동작한다. `--from`이 받는 단계 키를 확인하는 방법이기도 하다.

아래의 개별 명령이 러너가 호출하는 것들이다. 한 단계씩 손볼 때 직접 실행하면 된다. 다만
`runs/regen/`은 제자리에서 덮어써지므로, 한 단계만 다시 돌리면 하류 리포트가 이제는 존재하지
않는 입력을 서술한 상태로 남는다. `freshness.py`는 각 단계가 소비한 모든 산출물의 sha256을
그 단계 출력 디렉터리의 `_inputs.<stage>.json`에 찍는다 — **디렉터리당이 아니라 단계당 하나**라,
`runs/regen/s2_ml`을 공유하는 `train`과 `roweval`은 서로를 보증하지 못한다.
`stages.breakdown`은 매 실행 끝에 `runslayout.checkable_dirs()`가 지목한 모든 디렉터리를,
도장이 찍혔든 아니든 검사한다: 입력을 선언한 적 없는 단계는 깨끗한 것으로 읽히는 대신
`unchecked` 플래그를 띄운다. **보고할 뿐, 지우지는 않는다.**

`RUNBOOK.md` §3에 전체가 한 표로 있다 — 모든 단계, 그 게이트, 그리고 쓰는 파일 전부.

### `.md`는 옵트인, `.json`은 아니다

모든 단계는 매 실행마다 기계 판독용 산출물을 쓰고, 사람이 읽을 리포트는 **`--report`가
있을 때만** 렌더한다:

```powershell
python -m stages.s1_clean.run --report      # manifest.jsonl 옆에 census.md 추가
python -m stages.s2_ml.train  --report      # locoeval.json 옆에 locoeval.md 추가
```

이 플래그는 `stages/report.py` 한 곳에서만 등록되므로 단계 간에 어긋날 수 없고, 각 단계의
stdout은 실제로 쓴 산출물의 이름을 말한다. **게이트는 항상 기계 판독 산출물을 지목하고
`.md`는 절대 지목하지 않는다** — 이 저장소의 무엇도 `runs/` 밑 `.md`를 파싱하지 않으므로,
렌더된 페이지를 게이트로 삼았다면 "다 읽고 리포트를 지운 것"이 "그 단계가 아예 안 돈 것"처럼
보였을 것이다. 각 `.md`는 자기 쌍둥이의 순수한 렌더이고, 쌍둥이에 없는 숫자는 하나도 담지
않는다.

`runs/breakdown.md`는 `--report`의 의도된 예외다: 어느 하나에서 렌더된 게 아니라 모든 단계의
`.json`에서 조립되므로, 읽히기 위해 쓰인 유일한 페이지이며 플래그 뒤에 숨지 않는다.

### 데이터를 읽지 않는 검사들

```powershell
python -m stages.s2_ml.verify_features    # 벡터화된 스왑 카운트 == 스칼라 기준 구현
python -m freshness --self-test           # 신선도 검사기 자신의 음성 대조군
```

둘 다 무조건 가장 먼저 돈다. 밀리초밖에 안 들고, 코퍼스가 바뀌어도 무효화되지 않기 때문이다.
두 번째가 존재하는 이유: 조용히 발동을 멈춘 검사는 아무 문제 없는 파이프라인과 똑같이 보인다.

### S1 — 인구조사, 그다음 정제

```powershell
python -m stages.s1_clean.run      # 코퍼스를 재기만 하고 판단하지 않는다 -> runs\regen\s1_census
```

census는 `manifest.jsonl`을 만든다 (파일당 한 행: 세션, variant, 실측 레이트, 지터, 결측,
라벨 코드). `--report`를 주면 `census.md`도 나온다. clean 단계는 파일별 `channel_trust.json`을

디렉터리에 쓴다 — `--report`면 `clean_report.md`까지. 둘 다 `--out` 기본값이 올바른 자리를
가리키므로, 실험용으로 딴 데 보낼 때만 넘기면 된다.

### S2 — 학습하고, 호출자가 실제로 받는 것을 측정한다

```powershell
python -m stages.s2_ml.train      # 챔피언 + leave-one-rev-out 윈도우 CV -> locoeval.json
python -m stages.s2_ml.roweval    # 행 단위 곡선, 피험자별 표, reason 검증
```

`train.py`는 **윈도우**를 채점한다. 모델이 학습하는 단위가 그것이기 때문이다. 그런데 호출자는
CSV를 라벨링해서 **행**을 받고, 둘은 다르다 — 행은 그 행을 덮는 모든 윈도우를 평균해 채점되고,
이는 정확도와 임계값의 근거가 되는 신뢰도 순서를 둘 다 바꾼다. `roweval`은 재구현이 아니라
진짜 `label.py` 경로를 돌리며, 이 저장소가 인용하는 숫자는 그것이다. 가장 큰 보류 버킷이
실제로 무엇으로 이루어져 있는지 재는 `transitions_loro.json`도 여기서 나온다.

`--lockbox`를 주면 `roweval`은 `runs/keep/s2_ml`에 쓴다. 그 판독은 한 번 쓰면 소모되고 어떤
재실행도 정당하게 대체할 수 없으므로, 그 리포트와 입력 도장은 아무것도 다시 만들지 않는 쪽
트리에 산다. LORO 패스는 스펙에서 그때그때 다시 학습하며 나머지 단계와 함께
`runs/regen/s2_ml`에 남는다. **`roweval_lockbox.md`는 단계를 다시 돌려도 복구되지 않는다 —
시도하지 말 것.** 그 숫자들은 git에 추적되는 `runs/keep/s2_ml/roweval_lockbox.json`에 살아
있고, `roweval.render()`가 거기서 페이지를 다시 렌더한다.

**`roweval`의 숫자는 원시 경로에도 그대로 적용되며, 이건 두 번째 측정이 아니라 증명이다.**
`verify_serve`가 같은 녹화를 양쪽 경로로 라벨링해서 호출자가 받는 모든 열을 완전 일치로
비교한다 — confidence는 1e-9까지, 536,590행에서 불일치 0. 판정이 같고 정답이 같으면 정확도도
같으므로, 원시 경로를 따로 읽어서 새로 알아낼 것이 남지 않는다. 2026-08-07까지 `raweval`이
그 두 번째 판독을 했고 소수점 넷째 자리까지 일치했으며, 그래서 지웠다 — 서로 어긋날 수 없는
두 숫자는 독립적 확인처럼 읽히지만 독립적이지 않기 때문이다 (`caveats.md` §1.7).

### 원시 경로 검증

```powershell
python -m stages.s2_ml.verify_transform   # 네 개 컬럼을 원시에서 다시 만든다
python -m stages.s2_ml.verify_serve       # 같은 녹화를 두 경로로 라벨링, 행 대 행 비교
```

`transform.py`를 건드렸으면 둘 다 돌린다. **한 번도 실행되지 않은 다리는 소리 내어 틀릴 수
없고, 실제로 틀려 있었다**: 다수 variant의 시상면(sagittal) 축은 serve 경로를 만들기 전까지
잘못돼 있었다 (`caveats.md` §5). 둘 다 느리지만 둘 다 선택 사항이 아니다 — 플래그 뒤가 아니라
본체에서 돈다. 느리다는 것은 검사를 건너뛸 이유가 아니다.

### S3 — 모델을 쓰지 않는 제2의 의견

```powershell
python -m stages.s3_physics.label_audit   # 자기 라벨과 모순되는 시행은 어느 것인가
python -m stages.s3_physics.rate_audit    # 몸인가 시계인가? gyro_energy는 반드시 FAIL해야 한다
python -m stages.s3_physics.plausibility  # 파일 수준 경계: 보정한 다음, 주입한 결함에 쏜다
```

S3는 서로 다른 세 강도로 세 가지 일을 하고 그 순서는 의도적이다. 셋의 방어 가능성이 같지 않기
때문이다: **주석**을 감사하고 (강함 — 스왑 규칙에는 학습된 파라미터가 없고 라벨을 본 적이
없다), **파일**을 모델에 대해 경계 짓고 (중간), 개별 **윈도우**를 모델에 대해 막을 수 있다
(약함, 기본 OFF, 그리고 `roweval`이 논쟁 대신 측정한다). 그 크기를 정한 철회 기록은
`anchors.py`가 들고 있다.

`rate_audit`은 어떤 앵커가 몸을 서술하는지 샘플링 격자를 서술하는지 묻는다. `gyro_energy`는
그 음성 대조군이고 *실패하는 것이 정상*이다. `plausibility`는 깨끗한 녹화에 합성 채널 결함을
주입하고 어떤 경계가 그것을 잡는지 보고한다 — 플래그 뒤가 아니라 매 실행마다. 한 번도 발동한
적 없는 경계는 데이터가 깨끗하다는 증거가 아니기 때문이다.

### breakdown — 모든 단계를 한 페이지에

```powershell
python -m stages.breakdown     # -> runs/breakdown.md
```

**모든 실행의 마지막 단계**이자, 세 단계 전부와 코퍼스 스윕까지 읽는 유일한 단계다. 이 단계는
**아무것도 측정하지 않는다** — 모든 숫자는 그것을 소유한 산출물에서 복사되고 그 산출물 이름이
옆에 적히므로, 어떤 단계와도 어긋날 수가 없다. 파이프라인 전체를 한눈에 보려면
`breakdown.md`를 읽고, 숫자를 바꾸려면 그 숫자를 소유한 단계로 가라. `breakdown.json`은
없다 — 아무도 읽지 않던 기계 판독 쌍둥이였고, 읽을 사람이 나타나면 `build()`가 여전히 구조를
반환한다.

어떤 단계 리포트도 못 하는 두 가지를 한다. 첫째, **자기 결손을 스스로 진술한다**: 없는
산출물은 그것을 만드는 명령과 함께 §B에 인쇄된다. 돌지 않은 단계가 "할 말이 없는 단계"처럼
읽혀서는 안 되기 때문이다. 둘째, 기계적 규칙에서 **§A 플래그**를 올린다 — 목표 미달인 락박스,
너무 벌어진 피험자 편차, 하나의 variant나 연속된 세션에 몰린 코퍼스 파일들, 그리고 *체크인된
산문이 아직 살아 있는 헤드라인을 인용하고 있는지*. 마지막 것이 존재하는 이유는 `README.md`와
`caveats.md`가 둘 다, 다른 것을 측정한 실행에 대해 낡은 수치 쌍을 걸어 둔 채로 앉아 있었기
때문이다. 둘 다 "리포트를 우선하라"고 적어 두었지만, 그러지 않은 독자에게는 둘 다 여전히
틀린 문서였다. **이 한국어 문서(`README.ko.md`)도 같은 규칙으로 검사된다** — 번역이 자기가
번역한 숫자보다 오래 살아남지 못하게.

플래그는 판결이 아니다. 각각은 무엇을 들여다보라고 지목할 뿐, 아무것도 결론짓지 않는다.

### 녹화 하나에 라벨 붙이기

```powershell
python -m stages.s2_ml.label data\raw\20251024\00321_63_2025_10_24_15_32_0.csv
python -m stages.s2_ml.label some_annotated_trial.csv --preset high_precision
python -m stages.s2_ml.label_all                      # 모든 원시 파일 -> labeled_raw\
python -m stages.s2_ml.label_all --summary-only       # 스윕만, 파일별 CSV는 쓰지 않음
```

`label_all`은 챔피언이 확정된 뒤 `run_pipeline.py`의 16단계로도 돈다. 그래서 전체 실행은
그 실행의 다른 모든 것이 서술하는 바로 그 모델을 `labeled_raw/`가 서술하도록 남긴다. 다른
임계값이나 부분집합, 임시 `--out`이 필요하면 직접 호출하면 된다.

**두 가지 형태의 파일을 모두** 받고, 헤더의 family 마커를 이름으로 해석해 분기한다: 원시
장비 로그, 또는 `lpf_view` 파일. 원시 로그는 먼저 네 개의 `lpf_view` 채널로 다리를 놓고,
실행 시 어떤 하드웨어 리비전으로 해석됐는지, 실제로 어떤 두 채널을 읽었는지, 어떤
`channel_trust.json`을 참조했는지 출력한다.

**추측하는 대신 보류한다.** 이유를 명시하고 출력 파일은 만들지 않는다: 매핑되지 않은 하드웨어
리비전, 실측 치환이 지금 읽으려는 축과 모순되는 파일, 원래 deg/s가 아닌 자이로, 필터를 감당할
수 없는 최종 타임스탬프, 신뢰 기록 부재.

`label_all`은 `label.py`를 루프로 돈 것이다 — 모든 파일이 같은 `label_csv` 진입점을 지나므로
배치 실행이 작업자가 손으로 얻는 결과와 어긋날 수 없다. 파일 하나의 보류가 스윕을 끝내지
않는다: 각각을 잡아서 `abstentions.jsonl`에 기록하고 실행은 계속된다. 모든 원시 파일이
정확히 한 번씩 정산되는 것을, 바라는 게 아니라 assert한다.

### 출력 계약 — `Label` 대 `guess`

라벨링된 CSV는 **주석 코퍼스 자신의 여섯 컬럼으로 시작한다** — `Time`, 네 개의 `*_LPF` 특징,
`Label` — 그 뒤에 판정 컬럼을 붙인다:

| 컬럼 | 의미 |
|---|---|
| `Label` | 확정 판정: `0` 서 있음, `10` 걷기, `-1` 채점했으나 임계값 미만, `255` 이 행을 덮는 윈도우가 없었음 |
| `guess` | 임계값을 적용하기 *전*의 같은 판정: 조금이라도 채점된 모든 행에 `0` 또는 `10`, 아무것도 없었던 곳은 `255`. `-1`은 절대 나오지 않는다 |
| `confidence` | 앙상블의 `max(p, 1-p)`. `255` 행은 채점된 적이 없으므로 비어 있다. **보정된 확률이 아니다** — 순서일 뿐이고, 임계값과 비교하는 것 외의 용도는 없다. 하위 계산에 숫자로 넣지 말 것. `caveats.md` §2.6 참조 |
| `ambiguous` | 모든 `-1`과 `255` 행에서 `True` — `Label`을 해독하기 싫은 사람을 위한 평범한 불리언 |
| `reason` | 어떤 의심인가: `near_transition`, `weight_shift_or_step`, `model_split`, `posture_shift`, `low_excursion_gait`, `out_of_distribution`, `uncovered`. 확신한 행에서는 비어 있다 |

> `Label`은 "이 행을 써도 되는가"에 답하고 `guess`는 "모델은 뭐라고 봤는가"에 답한다 — 그리고
> `-1`은 전자를 주기 위해 후자를 파괴한다. **`Label != guess`는 채점된 뒤 보류된 행만 정확히
> 골라낸다.** 그게 곧 리뷰 큐인데, 모델의 의견이 잘려 나간 게 아니라 붙어 있는 리뷰 큐다.
>
> 두 보류 코드를 의도적으로 분리해 둔다: `-1`은 주석자 본인의 "봤는데 판정 못 하겠다"의 기계
> 버전이고, `255`는 `config.LABEL_UNKNOWN_MACHINE` — 판단할 만큼 측정된 게 없다는 뜻이다.
> 둘을 뭉뚱그리는 독자는 확신 없는 모델과 신호 부재를 구별할 수 없다. `--no-verdict`는
> `Label` 이후를 전부 떼어내 주석 파일과 모양이 구별되지 않는 파일을 남기고 (정확히 그것이
> 필요한 독자를 위해), `--full`은 프레임 전체를 유지한다. `label`과 `label_all`은 같은 두
> 플래그를 받고 기본 모양도 같다.

`label.REASONS`에는 reason 코드가 하나 더 있다 — `amplitude_ambiguous` — 그리고 **출하
출력에는 나타날 수 없다.** 기본값이 `False`인 `BAND_ABSTAINS`를 켰을 때만 쓰이기 때문이다.
켤 수 있게 남겨둔 건 의도다: 밴드를 이기는 표는 밴드가 바로 그 불신 대상으로 삼는 라벨에 대고
밴드를 채점한 것이라, 꺼 두는 건 판단이지 결론난 손실이 아니다 (`OPERATING_POINTS.md`).
`PHYSICS_CEILING` 플래그 뒤에 `physics_contradicts` 코드가 함께 있었지만 **둘 다 삭제됐다.**
그쪽은 결론이 났기 때문이다 — ceiling은 출하 지점에서 −11 errors고 p ≥ 0.95에서는 잡을 게
아예 없다. 다만 `roweval`은 가상의 ceiling을 계속 스윕해서, 그 철회가 기억이 아니라 측정으로
남게 한다.

**판정은 S2 단독의 것이다.** 행 단위 상태는 ExtraTrees 앙상블에서 나오고, 물리 진단은 그
의심에 *이름을 붙이는 데만* 쓰인다. 그러므로 `ambiguous`는 "앙상블이 확신하지 못했다"는
뜻이지, "두 의견이 갈렸다"는 뜻이 결코 아니다.

## S1이 실제로 하는 일과 그 이유

**컬럼을 위치가 아니라 이름으로 해석한다.** `NN_` 접두사는 식별자가 아니라 파일별 위치다.
`loco`는 **원시 파일 91개 중 80개**에서 인덱스 47에 있고 — variant `0fda484e`, 즉 나머지
**11개**에서는 인덱스 47이 `Step`이다 [measured 2026-08-04]. `Step` 자체도 variant에 따라
46 또는 47에 앉는다. 따라서 `df.iloc[:, 47]`은 코퍼스의 12%에서 펌웨어 걸음 수 카운터를
이동 상태로 읽으면서 **한 번도 에러를 내지 않는다**. 둘 다 구식 컬럼(레거시 알고리즘 출력 /
펌웨어 카운터)이고 clean이 잘라낸다. `DOMAIN_NOTES` §1.3 참고.

**위험한 것은 소수 쪽이다.** 어디서나 깨지는 위치 기반 읽기라면 첫 플롯에서 발견된다. 파일
80개에서 맞고 11개에서 틀리는 읽기는 멀쩡해 보이는데 멀쩡하지 않은 결과를 만든다.

**결측 구간에서 세그먼트를 자른다.** 결측은 아무 데나 생긴다. 파일은 연속 구간들의 자루이고,
분석 단위는 파일이 아니라 **세그먼트**다. 결측을 가로질러 리샘플하는 일은 결코 없다 — 그건
측정된 적 없는 데이터를 지어내는 것이다.

**레이트를 100 Hz로 정규화한다.** 코퍼스에는 두 시대가 있다: 이른 시기의 ~100 Hz와 이후의
500 Hz. 다운샘플링은 `[::5]`가 아니라 반드시 `scipy.signal.decimate(..., ftype='fir')`을
쓴다 — 순진한 데시메이션은 50 Hz 위의 모든 것을 보행 대역으로 접어 넣어 진폭이 온전한 가짜
신호를 만든다. 측정된 증명은 `DOMAIN_NOTES` §2.5. 어정쩡한 레이트들(99.3789 / 99.688 /
99.961 Hz)은 다른 장비가 아니라 *타임스탬프 양자화*(10 + 2⁻ᵏ ms)이고, 버리는 게 아니라
격자를 보정한다.

**측정된 채널만 남긴다.** 장비가 *측정하는* 것은 IMU 채널과 로드셀이다. Cadence, Stride
Length, GCP, 어드미턴스, PID 상태는 장비가 *계산한* 것이다. 계산된 컬럼은 관측이 아니라
펌웨어의 의견이다. 그것들을 버리면 스키마 variant들이 하나로 붕괴하고, 특징 집합에서
펌웨어 버전 신호가 제거된다. 예외 장치(`stages/s1_clean/config.py`의 `KEEP_EXCEPTIONS`)는
**현재 비어 있다** — 표준 == 측정, 단서 조항 없음. 유일했던 예외 `Hip_Deg_L/R`은 측정해 보고
잘렸다: 이미 남기고 있던 `Deg_Y`와 0.991 상관이었고, 그 잔차는 펌웨어의 영점 관례 외에는
아무것도 담고 있지 않았으며, 코퍼스 일부에서는 죽어 있었다. `DOMAIN_NOTES` §9 참고.

여기서 "측정된"은 *앱 계층에서 계산되지 않은*이라는 뜻이다. `Deg` 채널은 트랜스듀서 판독값이
아니라 IMU 자체의 온센서 융합 출력이다 — 남기긴 하지만, 그것을 정답으로 취급하기 전에
`DOMAIN_NOTES` §4.6을 읽을 것.

## 구조

세 단계. 단계 사이의 **인터페이스는 파일시스템뿐**이다 — 에이전트 간 메시징도, 메시지 큐도
없다. `run_pipeline.py`는 멍청한 시퀀서다: 각 단계를 순서대로 셸 아웃하고 게이트 산출물이
나타났는지 확인한다. 단계를 "도와주려고" import하는 일은 절대 없다 — 단계의 출력을 고쳐 쓸
수 있는 시퀀서는 아무도 문서화하지 않은 네 번째 단계일 테니까.

| 단계 | 결정론적 본체 | 에이전트의 역할 |
|---|---|---|
| **S1 clean** | 스키마 인구조사, 레이트 정규화, 결측 세그먼트화, 채널 신뢰 | `s1_exception` — 예외 큐 분류 |
| **S2 ml** | 윈도잉 + 특징, 학습 + locoeval, 보류가 있는 행 단위 라벨링, 행/원시 평가, 코퍼스 스윕 | `s2_experiment` — 도전자 제안. 결정은 에이전트가 아니라 `locoeval`이 한다 |
| **S3 physics** | 스왑 규칙 앵커, 레이트 불변성 감사, 주석 감사, 파일 수준 타당성 | `s3_label_review` — 주석 감사가 표시한 것을 판단 |

### 타협하지 않는 네 가지

1. **일은 코드가 하고, 그 일을 판단하는 것이 에이전트다.** 에이전트는 데이터 값을 만지지
   않고, 직접 수를 계산하지 않는다.
2. **조용한 변경 금지.** 실패는 격리 장부에 기록되고, 결정에는 근거가 글로 남으며, 신뢰도가
   낮으면 `needs_human`으로 올라간다.
3. **"최선"은 에이전트의 의견이 아니라 `locoeval`이 정의한다.** 에이전트는 선언적
   `ExperimentSpec`을 제안할 수 있다. 그것을 실행하고 채점하고 승격 규칙을 적용하고 모든
   결과를 — 기각까지 포함해 — `runs/keep/s2_ml/experiments.jsonl`에 기록하는 것은
   `experiment.py`다. 챔피언은 기록되고 지표로 정당화된 승격을 통해서만 바뀐다.
4. **모든 단계는 `DOMAIN_NOTES.md` 갱신으로 끝난다.** 발견은 대화가 아니라 영구 기록이 된다.

에이전트에게는 원시 데이터 삭제, 사람 검토 없는 `DOMAIN_NOTES.md` 편집, 챔피언 재학습이
결코 허용되지 않는다. 각 실행은 자기 `runs/keep/agent_runs/<date>_runN/` 디렉터리에 쓴다:
`run_meta.json` (그것을 만든 커밋), `costs.json` (에이전트별 지출), `system_prompt.txt`
(에이전트가 들은 내용 그대로). `PostToolUse` 훅을 통해 `run_log.jsonl`이 옆에 생기는데 —
도구 호출당 한 줄이므로, 에이전트가 도구를 하나도 안 쓴 실행은 이 파일을 남기지 않는다.

## 이 파이프라인이 평가받는 기준

> **어떤 h-medi 녹화에서든, 확정한 행에 대해 ≥95% 정확도로 서 있음/걷기를 라벨링하고, 나머지는
> 추측하는 대신 보류할 것.** 보류는 기능이다: 모호한 행도 판정, 신뢰도, 불확실한 이유, 그리고
> 저울질하던 대안을 받는다.

출하 임계값 0.85에서, 개발 피험자를 한 명씩 뺀 조건으로:
**커버리지 84.66%, 정확도 0.9901, 최악 피험자 `rev5` 0.9525.**

이 쌍은 **`runs/regen/s2_ml/roweval_loro.json`**에서 복사한 것이며 **`s2_roweval`을 다시
돌리면 무효가 된다.** `stages/breakdown.py`가 이 파일이 아직 살아 있는 쌍을 인용하는지
기계적으로 검사하고, 챔피언이나 임계값이 움직이는 순간 플래그를 올린다 — 둘이 다르면
`runs/regen/s2_ml/roweval_loro.json`을 믿고 이 표는 절대 믿지 말 것
(`python -m stages.s2_ml.roweval --report`가 페이지로 렌더한다).

> **이건 개발 피험자 수치다.** 봉인된 락박스 피험자 `rev8`은 **확정한 행에 대해 0.9269**,
> 커버리지 75.6%를 기록한다 — 거기서는 목표에 미달이고, 걷기 재현율 1.0000에 대해 서 있음
> 재현율은 0.5622다. 위의 어떤 숫자든 인용하기 전에 `caveats.md` §3.2를, 그리고 무엇이 얇고
> 무엇이 미검증이며 무엇을 의도적으로 뺐는지를 함께 읽을 것.

`rev8`은 **소진됐다** — 2026-08-03에 두 번, 2026-08-07에 한 번, 총 세 번 판독했고 셋 다
`caveats.md` §3.2에 기록돼 있다.
새로 봉인한 피험자 없이 네 번째로 읽어서는 안 된다. `--lockbox`는 이제 `--read-note` 없이는
실행을 거부한다 — 봉인을 쓰는 이유는 타이핑해야 하고, 그 문장은 산출물 안에 남는다.

## 여기 남아 있는 "h-care"의 의미

데이터와는 아무 상관이 없다. 산문에 잘못 실려 다니던 제품명이었고 2026-08-05에 정정했다.
코퍼스는 처음부터 h-medi였다. 작업 디렉터리는 2026-08-07까지 `h-care-champion-5219cd5`였고,
리모트에 맞춰 `hurotics-autolabel`로 개명했다 — 편집이 아니라 체크아웃 수준의 이동이다.
이 문자열이 아직 남아 있는 곳은 두 부류이고, 각각 의도적이다:

| 어디 | 왜 남기는가 |
|---|---|
| `runs/keep/agent_runs/*/system_prompt.txt`, `archive/runs/*/system_prompt.txt` | **문서가 아니라 증거다.** 이 파일들은 *에이전트가 정확히 무엇을 들었는지*를 기록하려고 존재한다. 하나라도 고치면 이미 일어난 실행에 대해 기록이 거짓말을 하게 되고, 같은 디렉터리의 모든 판정은 지금 적힌 그 텍스트 아래에서 내려진 것이다. |
| `labeled_raw/preset_sweep.json`, `runs/keep/agent_runs/*/run_log.jsonl` | 절대 경로를 담은 생성 산출물이라 쓰일 당시의 디렉터리 이름을 그대로 물고 있다. 다음 실행에 재생성되고, 그 문자열을 읽는 코드는 없다. |

`archive/needtowrite.md`는 **고쳤다.** "아카이브는 발견된 그대로 둔다"는 일반 규칙에 대한
예외이며, 근거는 그 파일이 `rev2_view` → `lpf_view` 개명에 대해 스스로 세운 선례다: 아카이브는
거기서 *다시 쓰기 위해* 존재하고, 코드가 더 이상 쓰지 않는 이름을 그대로 옮겨 적는 것은 그
결함을 다음에 쓰이는 문서로 실어 나르는 일이다.
